# Atmos — real-time weather dashboard

A single-page weather application built with React, TypeScript and Vite. It shows current
conditions, a 24-hour and 10-day forecast, interactive analytics charts, air quality, a
precipitation-radar map and a multi-location comparison — all from live data, on top of a
background that changes with the actual weather and time of day at the selected place.

No API keys, accounts or backend are required.

## Getting started

Requires Node.js 20.19+ (or 22.12+).

```bash
npm install
npm run dev        # start the dev server → http://localhost:5173
```

| Command             | What it does                                           |
| ------------------- | ------------------------------------------------------ |
| `npm run dev`       | Development server with hot reload                     |
| `npm run build`     | Type-check, then create the production build in `dist` |
| `npm run preview`   | Serve the production build locally                     |
| `npm run typecheck` | TypeScript only (`tsc --noEmit`, strict)               |
| `npm run lint`      | ESLint                                                 |
| `npm test`          | Unit tests (Vitest)                                    |

## Features

- **Location** — debounced worldwide search with autocomplete (keyboard accessible),
  optional device location (asked only when you press the button), click-to-pick on the
  map, recent places, favourites, and shareable URLs
  (`?lat=…&lon=…&name=…`). On a first visit the starting city is derived from the browser's
  time zone, so nothing is requested from you.
- **Hero** — large temperature, condition, feels-like, today's high/low, humidity, wind,
  precipitation chance, UV, plus a short summary sentence generated by deterministic rules
  from the data (`src/utils/weatherSummary.ts`).
- **Current conditions** — temperature, feels-like, wind (compass, gusts, Beaufort),
  humidity, dew point, sea-level and surface pressure with 3-hour tendency, UV index,
  sunrise/sunset arc with daylight, countdown and calculated solar elevation, visibility,
  cloud cover, precipitation amount/rate/chance, rain and snowfall totals, freezing level,
  sky condition with WMO code.
- **Hourly** — scrollable 24-hour strip linked to an interactive temperature chart
  (hover, click to select, "now" marker) and a detail panel for the selected hour.
- **Daily** — the provider's 10 forecast days, expandable rows, and a high/low chart.
- **Analytics** — temperature / feels-like / dew point, humidity, pressure, wind and gusts,
  precipitation (probability, hourly amount, accumulation), cloud cover, UV, and
  sun/daylight, over 24 h, 48 h, 3 days or the full range.
- **Air quality** — European AQI and US AQI shown separately on their own scales,
  PM2.5, PM10, NO₂, O₃, SO₂, CO, pollen where modelled, and a 48-hour AQI chart.
- **Map** — pan/zoom map with an observed precipitation-radar overlay, a time slider and
  playback for the past ~2 hours.
- **Compare** — up to four places side by side with a shared temperature chart.
- **Units** — °C/°F in the header; km/h, m/s, mph, knots; mm/in; hPa/inHg; km/mi;
  12/24-hour clock. Preferences persist in `localStorage`.
- **Backgrounds** — distinct scenes for clear day, clear night, partly cloudy (day/night),
  overcast (day/night), rain, heavy rain, thunderstorm, snow, fog, sunrise, sunset and
  extreme heat. A "Visual effects" setting (Full / Still / Off) and the operating system's
  reduced-motion preference both disable motion.
- **Resilience** — request timeouts, retry with backoff, rate-limit and malformed-response
  handling, cancellation of superseded requests, de-duplicated in-flight requests,
  loading skeletons, empty and error states with retry. When a refresh fails the last
  successful forecast stays on screen with a clear "may be out of date" banner.

## Data sources

| Purpose                 | Provider                                                                 | Key  |
| ----------------------- | ------------------------------------------------------------------------ | ---- |
| Forecast (current, hourly, daily) | [Open-Meteo Forecast API](https://open-meteo.com/en/docs)      | none |
| Place search            | [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api) | none |
| Air quality and pollen  | [Open-Meteo Air Quality API](https://open-meteo.com/en/docs/air-quality-api) (CAMS) | none |
| Naming a coordinate (device location, map click, link without a name) | [OpenStreetMap Nominatim](https://nominatim.org/release-docs/latest/api/Reverse/), falling back to [BigDataCloud](https://www.bigdatacloud.com/free-api/free-reverse-geocode-to-city-api) | none |
| Radar tiles             | [RainViewer public API](https://www.rainviewer.com/api.html)             | none |
| Base map tiles          | [OpenStreetMap](https://www.openstreetmap.org/copyright) standard tiles  | none |

Please note before deploying this anywhere public:

- Open-Meteo's free endpoints are for **non-commercial use** with fair-use limits
  (currently 10,000 calls/day) and require attribution, which the footer provides.
  Commercial use needs their paid API.
- The public `tile.openstreetmap.org` servers have a
  [usage policy](https://operations.osmfoundation.org/policies/tiles/) meant for light use.
  For real traffic, switch to a commercial tile provider by changing the two constants at
  the top of `src/components/weather/MapView.tsx`.
- RainViewer's free radar is limited to zoom level 7 and the past ~2 hours; the provider is
  isolated in `src/services/radarApi.ts`.

### What the data is — and is not

- Everything except the radar layer is **numerical-model output**, not a measurement from a
  weather station. The app labels it that way. Open-Meteo's "current" values are model data
  interpolated to 15-minute steps.
- The radar layer is an observation composite and is independent of the forecast.
- Solar elevation is calculated in the browser from date, time and coordinates
  (`src/utils/solar.ts`) and is labelled "calculated".
- A value the provider does not return is shown as "—", never as zero. No sample or
  placeholder weather data ships with the app.

### Refresh policy

These are application choices, not provider guarantees:

- Forecast: re-requested every 10 minutes while the tab is visible, when the tab becomes
  visible or the network returns with older data, when the location changes, and on demand.
- Air quality: cached for 30 minutes. Radar frame index: every 10 minutes.
- The last successful forecast for the six most recent places is kept in `localStorage` so
  it can be shown (marked as stale) if a later request fails. This is **not** offline
  support — there is no service worker, and the app says so when you are offline.

## Project structure

```
src/
  app/            App shell, settings and locations context providers
  components/
    layout/       Header, location search, settings menu, weather background
    weather/      Hero, condition cards, hourly, daily, analytics, air quality, map, compare
    charts/       Recharts views (lazy-loaded chunk), shared TimeChart, palette
    common/       Section, segmented control, meter, sparkline, skeleton, states
  hooks/          useWeather, useLocationSearch, useGeolocation, useAsyncResource, useNow
  services/       http (timeouts/retries/errors), cache, weather / geocoding /
                  air-quality / radar API clients
  types/          Normalised data models
  utils/          Response parsing and selectors, unit conversions, date formatting,
                  weather-code → condition/icon/scene mapping, summary rules, solar maths
  styles/         Tailwind theme, glass styles, scene and animation CSS
```

Design rules the code follows:

- Raw API responses are parsed and validated in one place
  (`utils/weatherTransformers.ts`); components only see typed, normalised data.
- Data is stored in canonical metric units and converted exactly once, at render time, by
  `utils/unitConversions.ts`.
- All timestamps are UTC instants rendered in the *location's* IANA time zone.
- WMO weather codes map to descriptions, icons and background scenes in
  `utils/weatherConditions.ts`.

## Testing

`npm test` runs 31 unit tests covering unit conversions, valid/invalid/partial API
responses, forecast selectors, weather-code and scene mapping, time-zone formatting, solar
position and shareable-URL parsing.

## Known limitations

- No offline mode (see above) and no severe-weather alerts — Open-Meteo does not provide
  official warnings.
- Radar coverage depends on national radar networks; large parts of the world have none.
- Pollen is only modelled for Europe; air-quality values are model estimates.
- The comparison view loads when places are added or the page is opened; it does not
  auto-refresh on the 10-minute cycle the main forecast uses.
- Interface text is English only; dates and numbers follow the browser locale.
